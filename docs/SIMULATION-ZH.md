# 0.3 本机模拟与调试

## 进入隐藏Debug

1. 正常主页只有真实相机连接入口。打开右上设置，再进入关于
2. 连续点击“版本0.3”7次，每次间隔不超过2秒
3. 设置页出现Debug，进入后点击“连接模拟设备”
4. 主界面显示简短“模拟”标识。现在可测试录像、模式和GPS页面
5. GPS页面的“开启模拟GPS”只使用人工坐标，不请求定位权限、不发送真实BLE
6. 设置→Debug可以进入故障测试、查看采样和发送统计、退出模拟或关闭Debug
7. 关闭Debug立即清除模拟；离开应用停止GPS并断开，下次进入恢复隐藏

真实相机连接或扫描期间不能启动模拟。故障测试可注入拒绝、仅ACK、丢包、错序、暂停状态/定位及断连。GPS模拟每秒产生一个样本，协议发送上限10Hz；时间戳保持原始测量时间。

## JVM回归

JDK17环境执行 `./test.sh`，运行32基础协议、106GPS、43模拟会话、18Debug门控检查，共199项。生产Protocol、RemoteSession、GpsData/GpsSourceRules与自写SimulatedCamera实际参与执行。

假相机是本项目的可控测试替身，不能替代真实BLE、手表GNSS或相机入片测试。

## Android界面测试

本次使用真正启动的官方Android11/API30 AOSP软件模拟器，运行交付APK。尺寸378×496像素，240dpi主验证、320dpi压力验证。实际截图、视频、覆盖和未覆盖项见 [0.3验收记录](ui-v03/REPORT.md)。

屏幕截图不是设计图。Android模拟器中演示的相机/GPS仍走显式模拟通道，不能冒充实体相机或真实定位。真实GPS路径拒绝mock标记。

## 官方工具

DJI官方仓库提供frame_check帧校验、connect_cmd_frame_builder连接帧构造、需要硬件BLE的GPS回放示例，未找到完整相机软件模拟器。我们生成的模式/GPS帧已通过官方工具CRC和结构交叉检查，见OFFICIAL-FRAME-CHECK.txt。检查不能证明相机接受、保存GPS或时间语义正确。
