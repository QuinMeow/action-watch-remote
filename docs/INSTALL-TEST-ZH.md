# 安装与真机测试

## 先确认
本包是调试原型，不是已验证产品。没有 OPPO Watch 4 Pro 或 Action 5 Pro 实机证据。普通 APK 的安装方式取决于手表系统版本和厂商限制；不要为本原型 root、解锁或关闭系统安全机制。

1. 在相机准备一张可用测试存储卡，留足电量和空间，先切到普通视频模式
2. 在手表确认 Android API >=26、可合法安装普通 APK、有 BLE 支持
3. 开启相机蓝牙；先退出可能占用相机连接的遥控器或手机应用
4. 如果系统要求，允许“附近设备”；Android11及更早系统扫描需要定位权限和系统定位开关，仅扫描时不会读取GPS坐标；0.2只有你开启GPS推送后才读取真实定位并发给当前相机

## 安装
使用手表厂商支持的安装方式。若你已主动开启并授权该手表的 ADB 调试，可在自己的电脑用官方 Android platform-tools：

```
adb devices
adb -s <已核对的手表序列号> install -r action-watch-remote-debug.apk
adb -s <已核对的手表序列号> shell am start -n dev.actionwatch.remote/.MainActivity
```

只对已核对的手表执行，不自动打开无线调试，不接受不认识的电脑授权。若系统拒绝安装，记录错误文本和系统版本；不要绕过安全警告。卸载包名：dev.actionwatch.remote。调试密钥仅为本次构建用途，以后换签名可能需要先卸载（会清除配对应用标识）。

## 首次验证（请按顺序）
1. 打开应用，点击扫描；列表含其它 BLE 设备，仔细核对相机名称/地址后选择
2. 如果出现“没有预期服务”，说明设备不符或固件服务不同，断开后重新核对
3. 手表显示4位码；在相机确认对应配对请求。不认识的请求应拒绝
4. 若配对失败，记录失败阶段，不连续反复授权。随机应用身份是否被相机接受尚未验证
5. 等待模式、相机电量和时长出现。按钮亮起才可发送命令
6. 点击开始一次，观察“等待相机确认”；在相机屏幕实际确认录像灯/计时，再比对手表状态
7. 等几秒，点击停止一次，在相机确认停止并回放测试文件
8. 连续快速点击，确认只能发送一个待完成操作
9. 在录像中主动断开/退出应用，确认手表不再显示可信实时状态；**录像会继续，必须在相机手动停止**
10. 再测拒绝配对、权限拒绝/撤回、蓝牙关闭、相机休眠、离开范围、满卡和低电量（不要让设备过热）

## 0.2：模式切换
先确认相机待机且状态新鲜，点击“模式：…”。选择之后按钮暂时锁定，ACK只显示已应答，必须等待相机实际mode状态匹配。录像、预录、休眠时不切换。若模式被拒绝或超时，以相机当前模式为准；不要假定所有固件都支持界面列出的模式。

## 0.2：真实GPS
1. 退出“本机模拟”，手动连接实际相机并完成配对
2. 点击“开启GPS”，阅读位置/速度/高度发往当前相机的提示，再开启
3. 允许精确定位，到开阔天空下等待GPS与GGA完整数据，可能需要较长首次定位时间
4. 界面会显示最近真实采样约多少Hz，协议发送上限10Hz，二者不是一回事
5. 没有NMEA、MSL海拔、速度/方向/精度或第二次高度样本时，保持暂停；不是自动使用假坐标
6. 超过2秒无新完整定位停止发送；拒绝mock标记定位；堵塞时跳过GPS帧，不妨碍录制控制
7. 手动关闭、断线、相机休眠或离开APP都会停止；下一次需要重新主动开启
8. 拍测试片后在DJI支持的软件中核对有无GPS/仪表盘数据，不以“帧已入队”作为素材已存GPS的证据

注意：手表系统是否开放GGA NMEA和所需精度字段尚未知。没有字段就无法启用安全的真实推送；应采集最小诊断后调整适配，不将缺失字段填0。差分垂直速度有噪声，不能用于安全导航。位置默认不保存到APP文件或日志。

## 设备就位后的ADB调试
当前阶段不连接你的电脑。设备准备好后，通过你选择并授权的电脑/ADB连接手表，先确认 `adb devices` 中的确切序列号、系统API、相机固件，再安装0.2 APK。无需root、不修改系统安全配置。

可读取应用启动错误：
```
adb -s <手表序列号> shell getprop ro.build.version.sdk
adb -s <手表序列号> install -r action-watch-remote-debug.apk
adb -s <手表序列号> shell am start -n dev.actionwatch.remote/.MainActivity
adb -s <手表序列号> logcat -d -s AndroidRuntime
```
只提供与崩溃相关的最小日志；不公开真实GPS、私人蓝牙地址或完整设备日志。之后按配对→状态→模式→录像→GPS的顺序逐项验证，分别记录已通过和未通过。

功耗说明：此原型前台保持屏幕亮起，GPS和蓝牙连续运行会耗电；没有进行OPPO真实续航测试。离开应用会断开和停GPS，不提供锁屏/后台持续轨迹服务。

本次0.2与此前0.1调试包的签名证书SHA256相同，versionCode从1升为2，正常Android系统可尝试`install -r`覆盖升级保留应用配对标识；OPPO是否允许仍需实际安装确认。未来自行构建若使用不同密钥，则不能直接覆盖。
